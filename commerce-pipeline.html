The problem

Running a small print-on-demand catalog means research, copywriting, design and listing work every week. Agents can do most of it, but an unattended agent with API keys can also publish junk, leak credentials or burn through rate limits overnight.

The goal was a pipeline that could run without me, and could be trusted to stop itself.

My role

I wrote the requirements, chose the stack and set every guardrail. Claude drafted the code against those requirements; I reviewed each change, ran the tests and decided what merged. I also operate it: the VPS, the credentials and the daily health report.

How it runs

It runs unattended on a VPS under systemd, cycling through build, design and maintain modes depending on publish limits and configured cooldowns.

The guardrails

  • CredentialsAPI keys and OAuth tokens stay in .env; .env.example documents the variables without values.
  • Scanninggitleaks runs pre-commit and again in GitHub Actions on every pull request, with a pip-audit dependency check.
  • OAuthCanva tokens come from an OAuth PKCE setup script, Shopify credentials from a verified setup script; both checked at preflight.
  • ValidationTitle length, tag count, price range and asset readiness checked before any live publish.
  • ResilienceExponential backoff on rate limits and server errors; publish limits and cooldowns prevent burst automation.
  • OperationsSQLite tracks queue state, listings, run logs, SEO reviews and sales, so failures are diagnosable.
