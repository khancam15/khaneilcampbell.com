The 30-second version

What I built, at a glance.

Business problem

A small online catalog needs research, design, and listing work every week. Done by hand, it does not scale. Handed to unattended AI agents with API keys, it risks junk listings, leaked credentials, and runaway API use.

Technical architecture

A scheduled loop on a VPS runs a six-agent CrewAI team on Claude for research and copy, Claude with Canva’s MCP server for design, and the Shopify Admin API for publishing. Two gates sit in the path: a credential check before any work and a validator before anything goes live.

Business value

The weekly catalog work runs without me, inside limits I set: a publishing cap, a cooldown, retry limits, and a daily report. Every step is logged, so a failure is diagnosable instead of silent. Live sales results come after the first month of publishing.

The problem

Running a small print-on-demand catalog means research, copywriting, design and listing work every week. Agents can do most of it, but an unattended agent with API keys can also publish junk, leak credentials or burn through rate limits overnight.

The goal was a pipeline that could run without me, and could be trusted to stop itself.

My role

I wrote the requirements, chose the stack and set every guardrail. Claude drafted the code against those requirements; I reviewed each change, ran the tests and decided what merged. I also operate it: the VPS, the credentials and the daily health report.

How it runs

It runs unattended on a VPS under systemd, cycling through build, design and maintain modes depending on publish limits and configured cooldowns.

The guardrails

  • CredentialsAPI keys and OAuth tokens stay in .env; .env.example documents the variables without values.
  • Scanninggitleaks runs pre-commit and again in GitHub Actions on every pull request, with a pip-audit dependency check.
  • OAuthCanva tokens come from an OAuth PKCE setup script, Shopify credentials from a verified setup script; both checked at preflight.
  • ValidationTitle length, tag count, price range and asset readiness checked before any live publish.
  • ResilienceExponential backoff on rate limits and server errors; publish limits and cooldowns prevent burst automation.
  • OperationsSQLite tracks queue state, listings, run logs, SEO reviews and sales, so failures are diagnosable.

When it fails

Every failure has a defined outcome. The pipeline stops, waits or reports; it never guesses.

  • Bad credentialsPreflight checks Shopify, Canva and Anthropic before any work starts. If one fails, the loop exits and nothing runs.
  • Invalid listingThe validator writes the error to the run log and halts that product. Nothing reaches Shopify.
  • API errorsRate limits and server errors retry at 2, 4 and 8 seconds, honoring Retry-After. Five failures in a row open a circuit breaker for five minutes.
  • Runaway publishingA weekly cap and a 24-hour cooldown limit how much can go live. At the cap, the loop switches to SEO maintenance only.
  • Silent failuresErrors go to a separate log, and the daily health report flags any product stuck for more than 48 hours. I read that report and the daily email digest.
