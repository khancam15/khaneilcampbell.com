The 30-second version

How the lab works, at a glance.

Business problem

Failed logons are constant on any Windows network. Most are typos; a few are password-guessing attacks. An analyst needs to tell them apart quickly, and the same way every time.

Technical architecture

In an isolated VirtualBox lab, a Kali VM attacks a Windows 11 VM over SMB. A Universal Forwarder ships the Security log to Splunk, an SPL threshold rule flags bursts of Event ID 4625, and a Python script pulls the hits through the REST API and drafts the case note.

Business value

Detection and first-pass triage become repeatable: the rule is written down, the threshold is explained, and every alert arrives with the same next steps. This is a lab build that rehearses the workflow a SOC runs on real alerts.

The problem

Failed logons are constant in any Windows estate. Most are a mistyped credential; a few are not. The goal was to find the difference reliably: identify anomalous authentication patterns, cut alert fatigue through threshold tuning and turn raw event data into a structured, repeatable response.

It is deliberately unglamorous work. The value is in the write-up: anyone picking this up later should be able to rebuild the query, understand why the threshold sits where it does and follow the same triage path.

My role

I built the lab in VirtualBox, ran an SMB brute-force attack from Kali Linux against a Windows 11 host, wrote the SPL detection and threshold alert in Splunk, and generated triage case notes in Python through the Splunk REST API.
