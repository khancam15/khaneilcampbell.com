Benjaire: engineering a real business.

Benjaire is my New York company, developing consumer brands and digital solutions. I treat its web platform as a product I own and operate: written requirements and decision records, a static Astro site on Cloudflare, a secured contact Worker, and automated checks on every change.

Visit benjaire.com View the repository
Why it matters

Real stakes, not an exercise.

A lab can be reset. A business cannot. Benjaire's site carries the company's credibility, its inbox and its customer enquiries, so every decision had to weigh cost, security, risk to email and what happens if a change goes wrong.

The previous site was three hand-written pages: duplicated navigation on every page, an empty brands section, a contact form that sent email straight from the browser with no server-side validation or bot protection, and security policy in a meta tag, which browsers ignore for anti-clickjacking rules.

Approach

Run like a product, not a page.

Requirements first

A requirements document ranks priorities: credibility, design, performance, security, search, maintainability, then cost. Every line is labelled confirmed, proposed, verify or future, so nothing unapproved is treated as fact.

Recorded decisions

Framework, hosting, DNS and email preservation, and form processing each have a decision record comparing the options. When Cloudflare changed how new projects are created, the hosting record was updated rather than worked around.

Approval gates

Milestones needed my approval, and changes to DNS, email routing and hosting each needed explicit sign-off. No login, database or customer portal is added without a defined business need.

AI-assisted delivery

I set the requirements, priorities and design direction; Claude drafted documents and wrote code against the approved spec. Every commit is authored by me with Claude as co-author.

Engineering

What was built.

Architecture

One shared Astro layout replaced the duplicated markup. Brands are content files validated at build time, and legacy .html URLs redirect permanently to clean paths.

Hosting and deployment

Cloudflare Workers Builds deploys main to production and gives each pull request its own preview URL. The move from GitHub Pages followed a written cutover runbook with a saved DNS export as the rollback.

Contact Worker

A Cloudflare Worker at /api/contact accepts posts only from the site's origin, rate-limits per IP, discards honeypot submissions, verifies Turnstile on the server and delivers through Email Routing.

Security headers

Real HTTP headers on every page: a Content Security Policy that allows inline scripts only by hash, HSTS and X-Frame-Options: DENY.

Quality gates

GitHub Actions run type checks, Worker unit tests, the build, link and SEO checks, and Playwright with axe for WCAG 2.2 AA on every change.

Protecting operations

Only the two website DNS records changed during the hosting move; mail records and Email Routing were left untouched. Credentials live only in Cloudflare, never in the public repository.

What it delivered.

Not yet launched: no consumer brand is public, and Digital Solutions client intake is in development. The site says so plainly rather than implying otherwise.

The lesson I took from it: writing requirements and decisions down first made AI-assisted development faster, not slower, and put security and SEO checks where they fail a build instead of relying on memory.
